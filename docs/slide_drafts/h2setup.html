H2 asks whether newer decision-based models give a better cost / latency tradeoff in physical safety settings. A decision model gets the scenario and a multiple choice question and returns a probability per option instead of writing a reply, which removes the format problems we saw scoring generated text and makes it fast. I compared Jev (closed, hosted), OpenJev (open, 26B total / 4B active, free tier), OpenAI's Decisions API (gpt-6-luna), Kev-4B (a 4B model hosted on Modal), and Qwen3.5-4B read through its softmax probs, which isolates ignoring generation from the architecture. Baselines are GPT-5, Mini and Nano. I varied prompt wording (short / full) and question mode (independent / cumulative, where later questions see earlier answers). Two combined designs are in results/part2_designs: route to GPT-5 when the decision model is unsure (D), or split the 4 questions between them (B). Scoring is the same as Fig 4 (exact letter, 319 items). Cost is API dollars per 1,000 items, and self-hosted / free tier models have no per-call price. Latency is the median per item.
